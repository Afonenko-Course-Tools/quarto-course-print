# Диагностика Print

Print проверяет публичный Body, фиксированную работу, native AST и ресурсы до материализации. Собственное сообщение содержит устойчивый ID, компонент Print, русский смысл, доступные источник/ID объекта/поле, связанные объекты и подсказку. Контекст указывает на входной объект. Print не приписывает строки временного JSON, Typst или HTML исходному QMD.

| ID | Смысл | Исправление |
| --- | --- | --- |
| `ADAPTER` | Публичный пакет не соответствует контракту; работа или вопрос не найдены; переданы закрытые поля/маркеры, неподдерживаемый AST/URL, некорректные ресурсы или небезопасное назначение. Также результат компиляции должен быть настоящим PDF. | Проверьте указанное поле и источник. Передайте `buildBodies(...).publicPackage`, существующий ключ работы, поддерживаемый публичный Body и фактические байты с текущим SHA-256. Укажите прямой путь результата без псевдонимов и символических ссылок. |
| `PRINT.INPUT_INVALID` | Не заданы обязательные аргументы CLI, входной файл невозможно прочитать либо его JSON некорректен. | Укажите `export.ts public-package.json course/work output-directory [header.json]`, доступные файлы и корректный JSON. |

`ADAPTER` остаётся общим ID адаптера; компонент Print и поле уточняют отказ. Новые узкие aliases не вводятся. Закрытые значения не включаются в сообщения. Некорректные поля вопроса сообщаются с `source` и ID вопроса; ошибки Body — с `condition` или `publicAnswer`. Ошибки байтов ресурса сообщаются с источником, `target` как ID и полем `data` либо `sha256`. Для выбранной работы сохраняется связанный источник/ID, когда они известны. Неизвестный источник или ID не выдумывается.

## Внешние инструменты и CLI

Отказ Pandoc/Typst остаётся отказом внешнего инструмента. Локальный Error имеет имя `ExternalToolFailure`, сохраняет `tool`, `exitCode`, `stdout`, `stderr` и `cause`. При невозможности запуска код завершения отсутствует; исходная причина сохраняется. Вывод не переводится и не распознаётся по регулярным выражениям для назначения semantic ID. Успешный процесс возвращает stdout, передаёт stderr без изменений однократно и не превращается в авторский отказ.

Собственный Error имеет стандартное имя `ExtensionDiagnostic` и свойство `code`. Это локальные обычные Error, без нового сериализованного отчёта, общего runtime-пакета или импортируемого класса. CLI выводит сообщение ожидаемого собственного или внешнего отказа один раз и завершается с ненулевым кодом. Неизвестное внутреннее исключение сохраняет stack.

## Результат при отказе

Ошибки пакета и байтов проверяются до компиляции. Native компиляция выполняется в отдельном временном каталоге; конечные PDF/JSON/ресурсы копируются после успешной проверки PDF и путей назначения. Отказ внешней команды не записывает новый конечный PDF. Уже существующий результат не подтверждает успешность новой попытки: проверяйте код завершения.

Проверки и отрицательные fixtures находятся в `tests/production.test.ts`, `tests/export.test.ts`, `tests/process.test.ts` и `tests/diagnostics-cli.test.ts`. Документация и [демонстрация](../examples/paper/README.md) содержат корректные сценарии.
